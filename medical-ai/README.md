# 医療AI 診察支援アプリ（プロトタイプ）

診察の音声対話から「議事録」「SOAPカルテ」「紹介状（診療情報提供書）ドラフト」「処方オーダ」までを自動生成し、
ワンタップで看護師・調剤側に連携するための Web アプリのプロトタイプです。

- フロントエンド: `frontend/`（Next.js App Router + TypeScript + Tailwind CSS）
- バックエンド: `backend/`（FastAPI、WebSocketでの音声/文字起こしストリーミング、LLM連携）

## 今すぐ試す（アカウント登録・APIキー一切不要）

「OpenAIのAPIキーを取得しないと動かせない」と思われがちですが、そんなことはありません。
このプロトタイプは **どこにも登録せず、APIキーなしで今すぐ全機能を試せます**（生成される
議事録・カルテ・紹介状・処方は `[MOCK]` 付きのダミー内容になりますが、画面の流れ・操作感は
本番と同じです）。

```bash
cd medical-ai
./start.sh
```

これだけで、バックエンドとフロントエンドが両方起動します。ブラウザで
`http://localhost:3000` を開き、試し用のアカウント（例: 医師 `demo-doctor` / `demodoctor2026`。
一覧は後述の「ログインと役割」）でログインすれば、受付リストからすぐに試せます。終了する時は
ターミナルで `Ctrl+C` を押してください。

（本物のAIによる生成を試したくなった場合のみ、後述の「バックエンドのセットアップ」を参考に
`backend/.env` に `OPENAI_API_KEY` を設定してください。あくまで任意のオプションです。）

上記はご自身のPC上だけで動かす方法です。**スマホなど他の端末からも開けるURLが欲しい場合**は、
次の「スマホ・どこからでも開けるURLを作る」を参照してください。

## スマホ・どこからでも開けるURLを作る（無料ホスティング）

インターネット上のどこからでも開けるURLを作るには、どうしても**どこかのサーバーにアプリを
置く（デプロイする）**必要があります。これは避けられない部分で、ホスティングサービスへの
**1回だけの無料アカウント作成**が必要になります（GitHubアカウントでログインするだけなので、
新しいパスワードを覚える必要はありません）。

ここでは無料枠のある [Render](https://render.com) を使う手順を説明します（クレジットカード登録不要）。
このリポジトリには、Renderが自動で設定を読み込む `render.yaml` を用意済みです。

1. ブラウザで https://render.com を開き、「**Get Started**」→「**GitHub**」でログインする
   （GitHubアカウントでのログインのみ。新規のメール・パスワード登録は不要）
2. 初回ログイン時に、このリポジトリ（`baturu-retto-line-bot`）へのアクセスを許可する
3. Renderのダッシュボードで「**New +**」→「**Blueprint**」を選択
4. 対象リポジトリを選び、ブランチは `claude/medical-ai-prompt-setup-2o9ief` を選択
   （このリポジトリ直下の `render.yaml` が自動検出されます）
5. 内容を確認して「**Apply**」をクリックすると、
   - `medical-ai-backend`（API）
   - `medical-ai-frontend`（画面）
   の2つが自動的にビルド・起動します（無料枠は初回起動やアクセスが少ない時間帯にスリープし、
   次のアクセス時に再起動まで30秒〜1分ほどかかることがあります）
6. 数分待つと、`medical-ai-frontend` の画面に表示されるURL
   （例: `https://medical-ai-frontend.onrender.com`）が、スマホ・PCどこからでも開ける本番URLです

**もし画面を開いても患者一覧が表示されない場合**（「エラー: Failed to fetch」等）:
- Renderのダッシュボードで `medical-ai-backend` サービスの実際のURLを確認する
- `medical-ai-frontend` サービスの「Environment」タブで `NEXT_PUBLIC_API_BASE` の値を、
  確認した実際のバックエンドURL（`https://` から始まる完全なURL）に書き換えて保存する
- 保存すると自動的に再デプロイされ、数分後に反映される

**注意: この方法で公開したものは「架空データだけのデモ」です。** Renderの無料枠は保存ファイルが
再起動のたびに消え、管理者を作るコマンドも実行できないため、パスワードが公開されている試し用アカウント
（`SEED_DEMO_USERS=true`）で動きます。本物の患者情報は絶対に入力しないでください。

（本物のAI生成を使いたい場合は、`medical-ai-backend` サービスの「Environment」タブで
`OPENAI_API_KEY` を設定してください。任意です。）

## アンビエントスクライブ ライブプレビュー（手動入力なしの自動生成）

診察セッション画面には、会話が進むたびに以下4項目を**手動入力なしで自動更新**する
「アンビエントスクライブ ライブプレビュー」があります。

- 主訴・症状の要約（chief_complaint）
- 治療方針・提案（clinical_reasoning）
- 処方内容・アドバイス（prescription_draft）
- 紹介状・診療情報提供書（referral_letter）

`GET/POST /api/sessions/{id}` のレスポンスに含まれる `live_draft` フィールドが上記4項目の
JSON構造です。この4項目はバックエンドAPIとしても取得できます。

**医師の文体を反映する仕組みについて**: 「この医師ならどう考え、どう表現するか」を実現するために、
モデルの追加学習（ファインチューニング）は行っていません（本プロトタイプの範囲外）。代わりに、
①画面上部の「医師プロファイル」欄に登録した文体・重視ポイントのメモと、②その医師が直近に
確定させたカルテの実例、の2つをプロンプトに自動で埋め込み、文体のみを模倣させています
（内容は毎回の会話の事実のみに基づき、過去の実例の内容が混入しないようプロンプトで明示的に禁止しています）。
本プロトタイプは医師アカウントを分離していないため単一プロファイルですが、実運用では医師IDごとに
複数プロファイルを保持する形に拡張する想定です。

## 重要：仕様からの変更点（コンプライアンス上の理由）

元の要望には「患者の要望（例:1ヶ月分ほしい）と院内ルール・保険適用のジレンマがある場合に、
"この病名であれば特例適用が可能" のような裏技的提案をポップアップする」という機能がありました。

この形のまま実装すると、**実際の病状と異なる診断名を保険請求のためだけに示唆・使用する**ことになりかねず、
医療機関にとって不正請求（診療報酬の不正取得）や医師法・保険医療機関及び保険医療養担当規則違反のリスクを
生む機能になってしまいます。そのため、本プロトタイプでは以下の**合法的な代替案エンジン**として実装しました
（`backend/app/services/prescription_compliance.py`）。

1. **既存診断の特例該当チェック** — 医師が実際にカルテへ記録した診断名（AIが提案・変更するのではない）が、
   長期処方等の正規の特例要件に合致するかを機械的にチェックし、該当する場合のみ提示する。
2. **院外処方せんへの切替提案**
3. **分割処方（複数回来院）の提案**
4. **自費（自由診療）処方の提案**（保険適用外の数量を希望する場合の適法な選択肢として）

いずれの提案にも「実際の臨床所見に基づく正確な診断記録が前提であり、保険適用のためだけに診断名を
変更することは不正請求に該当し得る」という免責・注意文言を必ず添付します。最終判断は常に医師に委ねます。

ルール（日数上限・特例条件）はサンプルデータです。本番運用時は院内・保険者の正式なマスタに差し替えてください。

### 薬剤候補の提案（AI・参考情報）

> **既定では無効です。** 患者ごとの薬剤選択を支援する機能は、販売・配布すると薬機法上の
> 「医療機器プログラム」に該当し得るため、該当性を専門家・PMDAに確認するまで「切」にしてあります。
> 試すときだけ `backend/.env` に `ENABLE_DRUG_SUGGESTIONS=true` を書いて起動し直してください
> （無効の間は画面にボタン自体が出ず、APIも 404 を返します）。

有効にした場合、処方オーダ画面の下部で「候補を表示」を押すと、SOAPカルテの **S（訴え）とA（評価）だけ** を材料に、
「○○はいかがでしょうか。」という形の薬剤候補を最大3件表示します
（`backend/app/services/llm_pipeline.py` の `suggest_drugs`、`POST /api/sessions/{id}/prescription/drug-suggestions`）。
処方適正化アドバイザーと同じく、安全側に倒した設計です。

- **表示するだけで処方欄には反映しない** — 「処方欄へ追加」ボタンは意図的に置いていません。結果はセッションにも
  保存されません。採用する場合は医師が添付文書等で確認のうえ、処方欄に自分で入力します。
- **用量・日数は提案させない** — AIが出すのは薬剤名・提案文・理由・一般的な確認事項のみ。
- **根拠の機械チェック** — AIには、根拠となる部分をS/Aから一字一句そのまま引用させ（`grounding_quote`）、
  その引用がS/Aに実際に含まれない提案はサーバー側で捨てます。カルテに無い症状・診断を創作して
  根拠にした提案は、画面に出ません（捨てた件数は画面に表示）。既に処方済みの薬剤の重複提案も捨てます。
- **診断名は提案・変更させない** — Aに診断が無ければ、症状への対症療法の候補のみを検討させます。
- **免責文言を必ず表示** — 薬物アレルギー・併用禁忌・腎/肝機能・妊娠授乳・添付文書上の注意など、
  AIが把握できない個別事情がある旨（`models.py` の `DRUG_SUGGESTION_DISCLAIMER`）。

## アーキテクチャ概要

```
[受付患者リスト] --選択--> [診察セッション画面]
                              |
                     マイク音声 (WebSocket)
                              v
                 [FastAPI /ws/sessions/{id}]
                              |
              RealtimeTranscriber (OpenAI Realtime API
              が利用可能ならそれを使用。APIキー未設定時は
              手動テキスト入力にフォールバックするシミュレータ)
                              |
                     文字起こし(議事録ベース) 蓄積
                              |
                    finalize() で LLM パイプライン実行
                              v
        +--------------------+--------------------+
        |                    |                     |
   SOAPカルテ生成      紹介状ドラフト生成     処方オーダ抽出
        |                    |                     |
        +--------- 医師が画面上で確認・修正 ---------+
                              |
                 処方適正化アドバイザー（合法的代替案）
                              |
                 ワンタップでスタッフ連携（看護師/調剤）
                              v
                    [スタッフ受信ダッシュボード]
```

## バックエンドのセットアップ

```bash
cd medical-ai/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # OPENAI_API_KEY を設定（未設定でもモックモードで動作）
uvicorn app.main:app --reload --port 8000
```

`OPENAI_API_KEY` が未設定の場合、LLM生成部分とリアルタイム音声認識は**モック/シミュレーションモード**で
動作し、UIの一気通貫フローを確認できます（生成物には `[MOCK]` の注記が付きます）。

## フロントエンドのセットアップ

```bash
cd medical-ai/frontend
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_BASE を設定（デフォルト http://localhost:8000）
npm run dev
```

`http://localhost:3000` で受付患者リストが表示されます。

## 主な画面/機能

- `/` 受付患者リスト — 本日の患者をワンクリックで選択しセッション開始
- `/session/[id]` 診察ダッシュボード
  - リアルタイム文字起こしパネル（マイク開始/停止、または開発用の手動テキスト入力）
  - 議事録から自動生成される SOAPカルテ（編集可能、ワンクリックコピー付き）
  - 紹介状（診療情報提供書）ドラフト（編集可能、ワンクリックコピー付き）
  - 処方オーダ（薬剤・用量・投与日数）＋ 処方適正化アドバイザーのポップアップ（いずれもコピー付き）
  - 薬剤候補の提案（AI・参考情報。既定は無効。表示のみで処方欄には反映しない）
  - スタッフ連携バー（看護師/調剤へワンタップ送信）

## 現場での使いやすさ

- **ワンクリックコピー**: SOAPカルテ・紹介状・処方オーダ・処方適正化アドバイザーの提案それぞれに
  大きな「コピー」ボタンがあり、既存の電子カルテ/レセコンの入力欄へそのまま貼り付けられる
  プレーンテキスト形式でクリップボードにコピーする（`lib/formatForCopy.ts`）。
- **編集のレスポンス改善**: SOAP・紹介状・処方オーダの各フィールドは、以前は1文字入力するたびに
  保存APIを呼んでいて編集がもっさりしていた。現在は入力内容を即座に画面(確定データ)へ反映しつつ、
  実際の保存は入力が止まってから自動的に行う（`lib/useFieldDebouncer.ts`）。フォーカスを外した
  瞬間にも即座に保存を確定させるため、保存し忘れは発生しない。長文も`AutoGrowTextarea`で
  自動的に高さが伸び、スクロールに埋もれない。

## 現場フィードバック（専門用語・ローカルルール）の反映方法

医療現場特有の言い回しや、診療科特有の処方ルールは、以下の2ファイルを編集するだけで
反映できる（他のコードを触る必要はない）。

- `backend/app/medical_rules.py` — 処方日数の上限、薬剤キーワードごとの上限日数、
  長期処方の特例要件に該当する診断名リストなど、処方適正化チェックのルール。
- `backend/app/custom_instructions.py` — AIへの指示文に追記する、現場特有の言い回し・
  記載ルール（例:「当院(整形外科)ではOの欄に関節可動域(ROM)を必ず記載すること」等）。
  SOAP・紹介状・処方抽出・議事録・ライブドラフトすべてのプロンプトに自動で反映される。

## エラー監視・リトライ

信頼性を高めるため、以下を組み込んでいます。

- **エラー監視(Sentry)**: バックエンドは `SENTRY_DSN`、フロントエンドは `NEXT_PUBLIC_SENTRY_DSN`
  を設定すると有効になります（未設定でもアプリ自体は問題なく動き、ログ出力のみになります）。
  - バックエンド: 未処理の例外をすべて `app/main.py` の共通ハンドラで捕捉し、サーバーログに
    フルスタックトレースを出力したうえで、ユーザーには生のトレースバックを見せない。
  - フロントエンド: `app/error.tsx` / `app/global-error.tsx` で画面描画中の例外を捕捉し、
    再試行ボタン付きの画面を表示する。`lib/monitoring.ts` の `reportError()` を各catch節から呼び、
    Sentry未設定でも最低限 `console.error` に残す。
- **LLM呼び出しのリトライ**: タイムアウト・レートリミット・一時的な接続断は
  `app/errors.py` の `call_with_retry()` が自動で最大3回リトライする(認証エラー等、
  リトライしても直らない種類は即座に失敗させる)。最終的に失敗した場合は
  HTTP 503 + 分かりやすい日本語メッセージを返し、`finalize` 中の失敗時はセッション状態を
  `generating` で固まらせず `in_progress` に戻して再試行できるようにしている。
- **音声ストリーミングの切断**: バックエンドは音声認識の上流接続が切れたことを検知して
  `{"type":"error","fatal":true}` をブラウザへ通知する。フロントエンド(`TranscriptPanel`)は
  意図しない切断を検知すると自動で数回再接続を試み、それでも繋がらない場合は
  「再接続」ボタンを表示する。処方適正化チェックなど他のAPI呼び出しにも、
  失敗時に押せる「再試行」ボタンを用意している。

## ログインと役割

すべての画面・APIはログインが必要です（`backend/app/deps.py`、`app/routers/auth.py`）。

| 役割 | できること |
|---|---|
| 医師 | 診察・録音・カルテ/処方/紹介状の作成と修正・看護師や薬局への送信 |
| 看護師 | 患者一覧とカルテの閲覧・連携の受信箱の閲覧・会話の手入力（修正や確定はできない） |
| 管理者 | 職員アカウントの作成・停止・パスワード再発行のみ（カルテは見られない） |

- **ID・パスワードは病院の管理者が作ります**（本人が勝手に登録はできません）。管理者が設定したのは仮パスワードで、
  本人は最初のログイン時に自分のパスワードへ変更します（変えるまで他の画面は使えません）。
- **最初の管理者**は、画面からは作れないので、`backend` フォルダで次のコマンドを実行して作ります。
  ```bash
  python -m app.cli create-admin
  ```
- **自動ログアウト**: 最後の操作から30分（`SESSION_IDLE_MINUTES`）で、サーバー側でもログインが無効になり、
  画面もログイン画面に戻ります。録音中は音声が届いている間「操作中」とみなすので、診察中には切れません。
- **パスワードの守り**: パスワードはそのままの形では保存せず、scrypt でハッシュ化して保存します。
  10文字以上・英字と数字の両方が必要です。5回続けて間違えると15分ロックします。
  IDが存在しないのか、パスワードが違うのかは区別して表示しません。
- ログイン中の目印（トークン）はブラウザの sessionStorage に置くので、タブを閉じると消えます。
  サーバーにはトークンそのものは保存せず、ハッシュ値だけを保存します。
- 録音用の WebSocket は、接続直後の最初のメッセージでトークンを送ってログインします
  （URLに入れるとサーバーのアクセスログに残るため）。
- **試し用アカウント**: `./start.sh` で起動したときだけ、架空のデモ用アカウントが作られます
  （`SEED_DEMO_USERS=true`）。本番では絶対に有効にしないでください。
  - 医師 `demo-doctor` / `demodoctor2026`、看護師 `demo-nurse` / `demonurse2026`、管理者 `demo-admin` / `demoadmin2026`

## データの保存

患者・診察セッション（文字起こし・カルテ・紹介状・処方）・連携記録・医師プロファイルは、
SQLite（1つのファイルに保存する、追加費用なしのデータベース）の `backend/storage/medical_ai.sqlite3` に保存されます
（`backend/app/data/store.py`）。アプリを止めて起動し直してもデータは消えません。

- 保存先は `backend/.env` の `DATABASE_PATH` で変えられます。
- ファイルは、アプリを動かしているユーザー以外は読めない権限（600）で作られます。
  `.gitignore` 済みで、Gitには入りません。
- データを全部消して最初のデモ状態に戻したいときは、アプリを止めてから `backend/storage/` を削除します。
- 1プロセスで動かす前提の作りです。複数台で動かす本番環境では、PostgreSQL等のサーバー型DBへ置き換えます
  （外から使う関数はそのままで、`store.py` の中身だけ差し替えられるようにしてあります）。
- 保存ファイル自体の暗号化はまだしていません（本物の患者データを入れる前に対応します）。
