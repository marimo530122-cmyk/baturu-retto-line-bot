# 医療AI 診察支援アプリ（プロトタイプ）

診察の音声対話から「議事録」「SOAPカルテ」「紹介状（診療情報提供書）ドラフト」「処方オーダ」までを自動生成し、
ワンタップで看護師・調剤側に連携するための Web アプリのプロトタイプです。

- フロントエンド: `frontend/`（Next.js App Router + TypeScript + Tailwind CSS）
- バックエンド: `backend/`（FastAPI、WebSocketでの音声/文字起こしストリーミング、LLM連携）

## 今すぐ試す（アカウント登録・APIキー一切不要）

「OpenAIのAPIキーを取得しないと動かせない」と思われがちですが、そんなことはありません。
このプロトタイプは **どこにも登録せず、APIキーなしで今すぐ全機能を試せます**（生成される
議事録・カルテ・紹介状・処方は `[MOCK]` 付きのダミー内容になりますが、画面の流れ・操作感は
本番と同じです）。

```bash
cd medical-ai
./start.sh
```

これだけで、バックエンドとフロントエンドが両方起動します。ブラウザで
`http://localhost:3000` を開けば、受付リストからすぐに試せます。終了する時は
ターミナルで `Ctrl+C` を押してください。

（本物のAIによる生成を試したくなった場合のみ、後述の「バックエンドのセットアップ」を参考に
`backend/.env` に `OPENAI_API_KEY` を設定してください。あくまで任意のオプションです。）

上記はご自身のPC上だけで動かす方法です。**スマホなど他の端末からも開けるURLが欲しい場合**は、
次の「スマホ・どこからでも開けるURLを作る」を参照してください。

## スマホ・どこからでも開けるURLを作る（無料ホスティング）

インターネット上のどこからでも開けるURLを作るには、どうしても**どこかのサーバーにアプリを
置く（デプロイする）**必要があります。これは避けられない部分で、ホスティングサービスへの
**1回だけの無料アカウント作成**が必要になります（GitHubアカウントでログインするだけなので、
新しいパスワードを覚える必要はありません）。

ここでは無料枠のある [Render](https://render.com) を使う手順を説明します（クレジットカード登録不要）。
このリポジトリには、Renderが自動で設定を読み込む `render.yaml` を用意済みです。

1. ブラウザで https://render.com を開き、「**Get Started**」→「**GitHub**」でログインする
   （GitHubアカウントでのログインのみ。新規のメール・パスワード登録は不要）
2. 初回ログイン時に、このリポジトリ（`baturu-retto-line-bot`）へのアクセスを許可する
3. Renderのダッシュボードで「**New +**」→「**Blueprint**」を選択
4. 対象リポジトリを選び、ブランチは `claude/medical-ai-prompt-setup-2o9ief` を選択
   （このリポジトリ直下の `render.yaml` が自動検出されます）
5. 内容を確認して「**Apply**」をクリックすると、
   - `medical-ai-backend`（API）
   - `medical-ai-frontend`（画面）
   の2つが自動的にビルド・起動します（無料枠は初回起動やアクセスが少ない時間帯にスリープし、
   次のアクセス時に再起動まで30秒〜1分ほどかかることがあります）
6. 数分待つと、`medical-ai-frontend` の画面に表示されるURL
   （例: `https://medical-ai-frontend.onrender.com`）が、スマホ・PCどこからでも開ける本番URLです

**もし画面を開いても患者一覧が表示されない場合**（「エラー: Failed to fetch」等）:
- Renderのダッシュボードで `medical-ai-backend` サービスの実際のURLを確認する
- `medical-ai-frontend` サービスの「Environment」タブで `NEXT_PUBLIC_API_BASE` の値を、
  確認した実際のバックエンドURL（`https://` から始まる完全なURL）に書き換えて保存する
- 保存すると自動的に再デプロイされ、数分後に反映される

（本物のAI生成を使いたい場合は、`medical-ai-backend` サービスの「Environment」タブで
`OPENAI_API_KEY` を設定してください。任意です。）

## 重要：仕様からの変更点（コンプライアンス上の理由）

元の要望には「患者の要望（例:1ヶ月分ほしい）と院内ルール・保険適用のジレンマがある場合に、
"この病名であれば特例適用が可能" のような裏技的提案をポップアップする」という機能がありました。

この形のまま実装すると、**実際の病状と異なる診断名を保険請求のためだけに示唆・使用する**ことになりかねず、
医療機関にとって不正請求（診療報酬の不正取得）や医師法・保険医療機関及び保険医療養担当規則違反のリスクを
生む機能になってしまいます。そのため、本プロトタイプでは以下の**合法的な代替案エンジン**として実装しました
（`backend/app/services/prescription_compliance.py`）。

1. **既存診断の特例該当チェック** — 医師が実際にカルテへ記録した診断名（AIが提案・変更するのではない）が、
   長期処方等の正規の特例要件に合致するかを機械的にチェックし、該当する場合のみ提示する。
2. **院外処方せんへの切替提案**
3. **分割処方（複数回来院）の提案**
4. **自費（自由診療）処方の提案**（保険適用外の数量を希望する場合の適法な選択肢として）

いずれの提案にも「実際の臨床所見に基づく正確な診断記録が前提であり、保険適用のためだけに診断名を
変更することは不正請求に該当し得る」という免責・注意文言を必ず添付します。最終判断は常に医師に委ねます。

ルール（日数上限・特例条件）はサンプルデータです。本番運用時は院内・保険者の正式なマスタに差し替えてください。

## アーキテクチャ概要

```
[受付患者リスト] --選択--> [診察セッション画面]
                              |
                     マイク音声 (WebSocket)
                              v
                 [FastAPI /ws/sessions/{id}]
                              |
              RealtimeTranscriber (OpenAI Realtime API
              が利用可能ならそれを使用。APIキー未設定時は
              手動テキスト入力にフォールバックするシミュレータ)
                              |
                     文字起こし(議事録ベース) 蓄積
                              |
                    finalize() で LLM パイプライン実行
                              v
        +--------------------+--------------------+
        |                    |                     |
   SOAPカルテ生成      紹介状ドラフト生成     処方オーダ抽出
        |                    |                     |
        +--------- 医師が画面上で確認・修正 ---------+
                              |
                 処方適正化アドバイザー（合法的代替案）
                              |
                 ワンタップでスタッフ連携（看護師/調剤）
                              v
                    [スタッフ受信ダッシュボード]
```

## バックエンドのセットアップ

```bash
cd medical-ai/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # OPENAI_API_KEY を設定（未設定でもモックモードで動作）
uvicorn app.main:app --reload --port 8000
```

`OPENAI_API_KEY` が未設定の場合、LLM生成部分とリアルタイム音声認識は**モック/シミュレーションモード**で
動作し、UIの一気通貫フローを確認できます（生成物には `[MOCK]` の注記が付きます）。

## フロントエンドのセットアップ

```bash
cd medical-ai/frontend
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_BASE を設定（デフォルト http://localhost:8000）
npm run dev
```

`http://localhost:3000` で受付患者リストが表示されます。

## 主な画面/機能

- `/` 受付患者リスト — 本日の患者をワンクリックで選択しセッション開始
- `/session/[id]` 診察ダッシュボード
  - リアルタイム文字起こしパネル（マイク開始/停止、または開発用の手動テキスト入力）
  - 議事録から自動生成される SOAPカルテ（編集可能）
  - 紹介状（診療情報提供書）ドラフト（編集可能）
  - 処方オーダ（薬剤・用量・投与日数）＋ 処方適正化アドバイザーのポップアップ
  - スタッフ連携バー（看護師/調剤へワンタップ送信）

## 本番導入に向けた注意事項（未実装/要対応）

- 認証・アクセス制御（医療従事者のみアクセス可能にする仕組み）
- 実際の電子カルテ/レセコンとの連携（HL7 FHIR等）
- 音声データ・会話内容の保存に関する同意取得、暗号化、保存期間ポリシー（個人情報保護法・医療情報ガイドライン準拠）
- 処方適正化アドバイザーのルールを院内・保険者の正式マスタへ差し替え
- 監査ログ（誰がいつ何を生成・修正・送信したか）
