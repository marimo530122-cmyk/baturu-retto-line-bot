# X投稿用の画像と、実話エピソードの書き方

## 画像の置き方

- 画像はこのフォルダ(`x_images/`)に置く。1投稿につき1枚まで
- 形式は `.jpg` / `.jpeg` / `.png` / `.webp`、1枚5MBまで
- ファイル名は半角英数字にする(例: `sashimi-moriawase-01.jpg`)
- 使うエピソードの `"image"` に `x_images/ファイル名` を、`"image_type"` に種類を書く
  - `"photo"` … 本人の実物写真(刺身の盛り合わせなど、本人の仕事の実物)
  - `"composite"` … 本人の写真をもとに作った合成のイメージ画像(吉○水産時代のイメージ。当時の実物写真ではない)
- `"composite"` の投稿には、プログラムが本文の最後に `※画像はイメージです` を自動で付ける。
  AIにも「当時の写真」など本物の写真だと思わせる書き方をさせない
- 画像が見つからない日は、文字だけで投稿する(止まらない)

## 実話エピソードの書き方(x_episodes.json に足す)

対象はブログの吉○水産時代の実話だけ(仕事の失敗談・成功談、総集編、怖い話など)。

`x_episodes.json` の `[ ... ]` の中に、次の形で1話ずつ足す(前の話との間に `,` を入れる)。

```json
{
  "kind": "story",
  "title": "【失敗談】(自分用の見出し。投稿には出ない)",
  "seed": "場面の種。ブログ記事のうち、一番いい一場面の出来事・セリフ・気持ちを書く。ここに無いことはAIは書かない",
  "url": "https://ameblo.jp/itaimarimo/entry-XXXXXXXXXXX.html",
  "hashtags": "#仕事の失敗談",
  "image": "x_images/sashimi-moriawase-01.jpg",
  "image_type": "photo",
  "text": "予備の固定文面(AIが失敗した日に使う本文。URL・ハッシュタグは書かない)"
}
```

- `image` と `image_type` は、画像なしの話なら2つとも書かない
- 画像の使い分け:
  - 目利き・技術・お客さんとの話 → 本人の実際の刺身盛り合わせの写真(`"image_type": "photo"`)
  - 師匠・先輩との人間ドラマの話 → 当時の姿のイメージ画像(`"image_type": "composite"`)
- ハッシュタグは1投稿2個まで。共通タグ `#吉〇水産の実話` はプログラムが必ず付けるので、
  `hashtags` には足したいタグを1個だけ書く(書かなくてもよい)。
  タグでは丸印「○」ではなく漢数字の「〇」を使う(「○」だとXがタグをそこで切ってしまう)
- AIは1行目をセリフか現場の情景から書き始める
- 本文はAIが毎回 `seed` から一場面だけを書く。続きは `url` のブログ記事へのリンクで誘導する
  (リンク・ハッシュタグはプログラムが付ける)
- Xは日本語1文字を2と数えて280まで。リンクとハッシュタグの分があるので、本文は全角100字前後になる。
  `text` もそのくらいの長さにする
- 会社名は「吉○水産」と書く(1文字を○で伏せる表記)。`seed` に実名があってもよい。投稿文では、AIの文も `text` も
  プログラムが必ず「吉○水産」に置き換える
- それ以外の実在の人物名・店名は投稿に出さない
- 実話は `x_episodes.json` に並んだ順に1日1本ずつ投稿される(続き物は順番どおりに並べる。最後まで行ったら1本目に戻る)。
- 投稿されるのは実話(`"kind": "story"`)だけ。既存の宣伝ネタ(罰ゲームルーレット等)はファイルに残っていても投稿しない。
  実話が0本の日は投稿しない

## 保留と、出さない名前

- `"hold": true` を付けた話は、登録だけして投稿しない(本人の確認待ちなど)。並び順からも外れる
- 保留を外す(`hold` を消す)のは、その話の投稿予定日より前にする。過ぎてから外すと、後ろの話が1日ずつずれて1本重複する
- 吉○水産のほかに、投稿に出さない名前がある(テナントの施設名・次の職場の会社名と店名・人の呼び名など)。
  種(`seed`)にも書かない。`--check` とAIの文の見張りで止める(`x_broadcast.js` の `OTHER_REAL_NAMES`)
- 一人称は「俺」。予備の文面に「私」「僕」があると `--check` で止まり、AIの文にあれば固定文面に切り替わる

## 返信のアフィリエイト枠(affiliate_items.json)

決めた曜日だけ、その日の本編(実話)への返信として、道具の紹介と Amazon リンクを1件つなげる。
本編にはリンクを入れない。差し替えるのは `affiliate_items.json` の `text` と `url` だけ。

```json
{
  "weekdays": ["wed", "sat"],
  "items": [
    {
      "id": "masahiro-gyuto-21",
      "text": "紹介文(本文だけ。【PR】・リンク・#PR は書かない)",
      "url": "https://www.amazon.co.jp/dp/XXXXXXXXXX?tag=scnr5301-22"
    }
  ]
}
```

- `weekdays`: 返信する曜日(`sun` `mon` `tue` `wed` `thu` `fri` `sat`)。日付の区切りは朝9時
- `items`: 紹介が複数あると、返信日ごとに上から順番に回る。一時的に外すときは `"enabled": false`
- 返信は「【PR】紹介文 / ▶ リンク / #PR」の形にプログラムが組み立てる
- 価格は書かない(変わるため)。「買った」とは書かず、「現場で手入れして使ってきた」と書く
- `url` には必ずトラッキングID(`?tag=scnr5301-22`)を付ける

## 書いたら点検する

`x_episodes.json` や画像を GitHub に入れると、Actions の「X投稿ネタの点検」が自動で動き、
書き方の間違い・画像の置き忘れ・ファイル名の打ち間違い・文字数オーバーを知らせる。
手元では `node x_broadcast.js --check` で同じ点検ができる。
