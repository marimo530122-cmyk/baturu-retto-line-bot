# 通院カルテ&処方箋 自動記録の仕組み

## これは何？

奥様の通院に付き添ったときのメモを、スマホから Googleドライブの決まったフォルダに
置くだけで、

1. AI（Gemini）が「症状」「診断・決定事項」「やることリスト」「アドバイス」など
   13項目の「カルテ(現状の記録)」と「処方箋(次のアクション)」に整理し、
2. もう一つのAI（Jev）が「変な内容になっていないか(元のメモと食い違っていないか)」
   をチェックし、
3. 問題なければ1枚のカルテ記録として保存する

という一連の作業を、パソコン側で自動的にやってくれる仕組みです。

`realtime-minutes`アプリの「通院カルテモード」(ブラウザでその場で録音・分類する
ワンタップの仕組み)とは別物で、こちらは**あとから振り返って、より詳しい記録を
1枚にまとめたいとき**用です。

## 普段の使い方(セットアップが終わったあと)

**やることは1つだけ**: スマホから、決められたGoogleドライブのフォルダに、
通院メモのテキストファイル(またはGoogleドキュメント/スプレッドシート)を置く。

それだけです。あとは自動で処理され、`output/` フォルダに記録(JSONファイルと
読みやすいMarkdownの「カルテ&処方箋」ファイル)ができます。

内容が変(元のメモと全然違う、項目が抜けている等)だと判断された場合は、
記録は作られず、`logs/run.log` にエラーとして記録されます(壊れた記録を
残さないための安全装置です)。

### カルテに含まれる項目

| カルテ(現状の記録) | 処方箋(次のアクション) |
| --- | --- |
| 受診概要 | やることリスト(期限つき) |
| 症状・様子 | 医師からのアドバイス・注意点 |
| 決定事項(診断・治療方針) | 参考にすべき資料・紹介先 |
| 未解決の懸念・不安 | 次回受診時に確認すべきこと |
| これまでの経緯・背景 | やってはいけないこと(NG事項) |
| 想定される費用・時間 | |

## 初回セットアップ(最初の1回だけ、技術的な作業が必要)

ここから先は、パソコンの操作に慣れている人(または依頼した相手)向けの手順です。
一度設定してしまえば、その後は上の「普段の使い方」だけで済みます。

1. 3つの「鍵」(パスワードのようなもの)を用意する
   - **Googleドライブの鍵**: フォルダの中身を読むための「サービスアカウント」という
     Googleの仕組みで発行する。発行したら、対象のGoogleドライブフォルダを
     その鍵の持ち主(メールアドレス)と共有しておく。
   - **Geminiの鍵**: Google AI Studio で発行する(`GEMINI_API_KEY`)。
   - **TypeSafe(Jev)の鍵**: TypeSafeのサイトで発行する(`TYPESAFE_API_KEY`)。
     ⚠️ この鍵は絶対にチャットやメール等の平文で他人に見せないこと。
     もし誤って見せてしまった場合は、使う前に必ずTypeSafe側で作り直す(ローテーション)。

2. `automation` フォルダの中で、以下を実行する:

   ```bash
   cd automation
   npm install
   cp .env.example .env
   ```

3. できた `.env` というファイルを開き、1で用意した3つの鍵と、
   Googleドライブの対象フォルダのID(フォルダのURLの一部)を書き込む。
   `.env` は他人に見せたり、GitHubにアップロードしたりしないこと(そのための
   仕組みは既に用意済み)。

4. 試しに1回動かしてみる:

   ```bash
   node run.js
   ```

   `output/` フォルダにファイルができていれば成功。

## プライバシーについて

通院メモには奥様の体調・病状という、とてもプライベートな内容が含まれます。
この仕組みは、メモの内容をGoogle(Gemini)とTypeSafe(Jev)という外部のAIサービスに
送って処理します。この点は把握した上で使う前提で作っています。

## ファイルの中身(参考)

| ファイル | 役割 |
| --- | --- |
| `fetch-data.js` | Googleドライブの指定フォルダから最新のメモを取ってくる |
| `gemini-extract.js` | メモをカルテ&処方箋の13項目に整理する |
| `validate.js` | 整理された内容が変になっていないか2段階でチェックする(安全装置) |
| `run.js` | 上の3つを順番に実行する、本体のスクリプト |

このリポジトリの `docs/daily-logs` に溜まる別の仕組み(`scripts/process_memo.py`、
魚屋さんの業務メモ用)とは別物で、そちらには手を加えていません。

## 今後の注意点(技術的な宿題)

- `validate.js` のJev(TypeSafe)とのやり取り部分は、開発中にTypeSafeの公式サイトへ
  接続できない環境だったため、正式な仕様書で確認できていません。本格的に使う前に、
  詳しい人に https://docs.typesafe.ai/api.md を確認してもらい、必要なら
  `validate.js` を直してもらってください。
- 今はスマホからGoogleドライブへの保存は手動です。「フォルダを開いて置く」操作が
  面倒な場合、別の受け取り方に変える相談も可能です。
- 「決まった時間に自動でチェックする」仕組み(定期実行)はまだ作っていません。
  今は `node run.js` を手動で実行する必要があります。
